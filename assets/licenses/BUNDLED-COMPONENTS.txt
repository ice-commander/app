Ice Commander — bundled third-party components
==============================================

Ice Commander itself is licensed under MIT OR Apache-2.0; see LICENSE-MIT.txt and
LICENSE-APACHE-2.0.txt in this directory.

This file lists the third-party libraries shipped alongside the application, the exact
version of each, and where its corresponding source can be obtained. It exists so that the
LGPL and GPL requirements on source availability are met. A dash in place of a version
means the library does not state one.

Linux packages (.deb / .rpm / Arch) bundle none of the libraries below; GTK and everything
else comes from the distribution.

fakelzo (in place of lzo2) — MIT                                    Windows, macOS
    NO LZO CODE IS SHIPPED IN EITHER BUNDLE. The file named liblzo2.2.dylib (macOS) or
    liblzo2-2.dll (Windows) is NOT Oberhumer's LZO, which is GPL-2.0-or-later. It is
    src/gplstubs/fakelzo/fakelzo.c, our own MIT-licensed code exporting the only two symbols
    libcairo-script-interpreter imports (lzo2a_decompress, lzo2a_999_compress), which
    report failure instead of compressing. No LZO code is used; only the two function
    signatures and one error code are shared.

    Why it exists at all: the real library reaches the bundle through a chain of optional
    dependencies nobody asked for —

        libgtk-4 -> libcairo-script-interpreter -> liblzo2

    and the loader requires it to be present because the interpreter links it. Nothing in
    the application reaches that code. Measured, not assumed: a build with an instrumented
    stand-in logged ZERO calls across a full session — both panels, image and PDF preview,
    video playback, the editor, settings and the terminal.

    macOS:   builder/osx.sh overwrites the copy dylibbundler pulled in, before signing,
             and refuses to sign if real LZO symbols remain.
    Windows: src/gtk-app/setup.nsi excludes liblzo2-2.dll from the artifacts tree with
             `File /r /x` and packs ours instead — so the GPL library is never placed in
             the installer archive, which is what matters for distribution.
             builder/check-bundle-licenses.sh --strict fails the build if a real one is
             not excluded and replaced.

    Consequence: cairo-script serialisation, a GTK debugging facility, does not work in
    these builds. Nothing the application offers depends on it.

    Source:   src/gplstubs/fakelzo/ in this repository, with build scripts for both
              platforms and a README covering the reasoning and the measurement.

    The Ice Commander source tree itself remains MIT OR Apache-2.0. The Linux packages
    need no stand-in: they bundle no libraries.


fakejbig (in place of libjbig) — MIT                                Windows
    The file named libjbig-0.dll is NOT JBIG-KIT, which is GPL-2.0-or-later. It is
    src/gplstubs/fakejbig/fakejbig.c, our own MIT-licensed code exporting the ten symbols
    libtiff-6.dll imports (jbg_dec_init, jbg_dec_in, jbg_dec_getsize, jbg_dec_getimage,
    jbg_dec_free, jbg_enc_init, jbg_enc_out, jbg_enc_free, jbg_newlen, jbg_strerror):
    the decoder reports an error and the encoder emits nothing. No JBIG-KIT code is used;
    only the function signatures and one error code are shared.

    It arrives the same way as liblzo2, through load-time imports nobody asked for —

        libgtk-4 / libgdk_pixbuf -> libtiff -> libjbig

    src/gtk-app/setup.nsi excludes the real libjbig-0.dll with `File /r /x` and packs
    ours instead, and builder/check-bundle-licenses.sh --strict checks that it still does.

    Consequence: a TIFF compressed with JBIG, a bi-level format for faxes and scans, does
    not open. Nothing the application offers depends on it.

    macOS: Homebrew's libtiff does not link libjbig, so there is nothing to replace;
    builder/osx.sh would replace one and refuses to sign if a real one remained. The
    Android stack's libtiff does not link it either.

    Source:   src/gplstubs/fakejbig/ in this repository, with build scripts and a README
              covering the reasoning and the measurement.


fakeidn2 (in place of libidn2) — MIT                                Windows
    The file named libidn2-0.dll is NOT libidn2. libidn2 is LGPL-3.0-or-later OR
    GPL-2.0-or-later, but its build links the gnulib made for the idn2 command-line program
    into the library too, and with it gnulib's progname module, which is GPL-3.0-or-later;
    MSYS2's DLL carries it. This is src/gplstubs/fakeidn2/fakeidn2.c, our own MIT-licensed
    code exporting the five symbols libcurl-4.dll and libpsl-5.dll import
    (idn2_check_version, idn2_free, idn2_lookup_u8, idn2_lookup_ul, idn2_to_unicode_8z8z).
    idn2_check_version accepts no version, so curl treats internationalised domain names as
    not supported, and the conversions report an error. No libidn2 code is used; only the
    function signatures and one error code are shared.

    It arrives through load-time imports nobody asked for —

        libadwaita -> libappstream -> libcurl -> libidn2, and libcurl -> libpsl -> libidn2

    libadwaita uses AppStream only for an About dialog built from appdata, which the
    application does not build. Measured under Wine: the application, started with a
    stand-in logging every call, made none.

    src/gtk-app/setup.nsi excludes the real libidn2-0.dll with `File /r /x` and packs ours
    instead, and builder/check-bundle-licenses.sh --strict checks that it still does and
    that ours exports everything the bundle imports from it.

    Consequence: the curl in this bundle refuses a URL whose host name is not ASCII.
    Nothing the application offers goes through curl.

    Source:   src/gplstubs/fakeidn2/ in this repository, with build scripts and a README
              covering the reasoning and the measurement.

GCC runtime — GPL-3.0-or-later WITH GCC-exception-3.1               Windows
    libgcc_s_seh-1.dll and libstdc++-6.dll, from MSYS2's GCC 15.2.0 ("Rev8, Built by
    MSYS2 project"), with parts of the same runtime linked into ice-commander.exe, as into
    any program GCC links. GTK, cairo, HarfBuzz, Graphite2, Fontconfig, pixman, librsvg,
    libjpeg-turbo, LERC and GStreamer were compiled with GCC and import them, so they
    cannot be left out. They are GPL code, shipped under the GCC Runtime Library Exception
    3.1, which lets programs compiled with GCC and linked against them be distributed on
    their own terms.

    libwinpthread-1.dll, mingw-w64's winpthreads, comes with them; it is MIT AND
    BSD-3-Clause.

    Source:   https://repo.msys2.org/mingw/sources/mingw-w64-gcc-15.2.0-8.src.tar.zst
              (MSYS2's source package), https://gcc.gnu.org/ and https://www.mingw-w64.org/
    License:  GPL-3.0.txt and GCC-exception-3.1.txt


Bison-generated parsers — GPL-3.0-or-later WITH Bison-exception-2.2 Windows, macOS
    GStreamer's pipeline parser (libgstreamer-1.0-0.dll) and gettext's plural-form parser
    (libintl-8.dll on Windows, libintl.8.dylib on macOS) are generated by Bison and carry
    its parser skeleton, which is GPL-3.0-or-later with the Bison exception. The exception
    lets a larger work that contains the skeleton be distributed under terms of its
    author's choice, so each library stays under its own licence.

gdk-pixbuf's macOS-icon loader — LGPL, despite the string saying "GPL"          Windows
    Part of libgdk_pixbuf-2.0-0.dll, and of the separate loader libpixbufloader-icns.dll.
    Noted here because every licence scanner finds it.

    The library reports "GPL" for that one format and "LGPL" for the other fourteen. The
    licence is LGPL, stated in the header of the source file itself, unchanged since the
    file was added in 2007:

      "This library is free software; you can redistribute it and/or modify it under the
       terms of the GNU Lesser General Public License ... version 2 of the License, or
       (at your option) any later version."

      https://gitlab.gnome.org/GNOME/gdk-pixbuf/-/blob/2.44.4/gdk-pixbuf/io-icns.c#L6-17

    The "GPL" on line 521 of that same file fills a display field returned by
    gdk_pixbuf_format_get_license(). It contradicts the file's own header, gdk-pixbuf's
    COPYING (LGPL-2.1) and Debian's copyright file, which puts GPL-2+ only on tests/* and
    thumbnailer/*. An upstream typo, not a licence.

      https://gitlab.gnome.org/GNOME/gdk-pixbuf/-/blob/2.44.4/gdk-pixbuf/io-icns.c#L521

Rust dependencies
    Every Rust crate compiled into the desktop binaries is listed with its license in
    THIRD-PARTY-LICENSES.md, in the source repository and in the application under
    Settings → About → Licences and components. The Android build adds jni 0.21.1,
    ndk 0.8.0 and ndk-context 0.1.1 (MIT OR Apache-2.0), and oboe and oboe-sys 0.6.1
    (Apache-2.0), which compile in the Oboe library listed above.

    zstd-sys compiles Meta's Zstandard 1.5.7 C library into every binary. It is
    BSD-3-Clause or GPL-2.0, at your option, and is used under BSD-3-Clause:
    https://github.com/facebook/zstd


Web interface
    The web interface built into every binary contains React and React DOM 19
    (https://github.com/facebook/react) and xterm.js 6 with @xterm/addon-fit
    (https://github.com/xtermjs/xterm.js); all are MIT.


Obtaining source
    For any component above, the linked upstream repository at the stated version is the
    corresponding source. For the MSYS2 builds, the package page on packages.msys2.org
    links both the upstream release and the MSYS2 build recipe; for the Homebrew builds,
    https://formulae.brew.sh/ does the same. If you need a copy we can provide directly,
    write to support@icecommander.com.
